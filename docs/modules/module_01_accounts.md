# Module 01 — บัญชีผู้ใช้ + หน้าแรกลูกค้า + หน้าไรเดอร์ + จัดการพนักงาน

## 1. ทำอะไรไปแล้ว

### บัญชีผู้ใช้ (`apps/accounts`)
| ส่วน | ไฟล์ | ทำไม |
|---|---|---|
| User model | `models.py` | ตารางเดียวทุกบทบาท แยกด้วย `role`: CUSTOMER / KITCHEN / RIDER / OWNER · ล็อกอินด้วยอีเมล · id เป็น UUID · อีเมลเก็บตัวเล็ก + unique แบบไม่สนตัวพิมพ์ (constraint ใน DB) |
| สมัคร / ล็อกอิน / ออก | `views.py`, `services/auth_service.py` | ลูกค้าสมัครเองได้ · พนักงานสมัครเองไม่ได้ · ออกจากระบบต้อง POST |
| หน้าแรกตามบทบาท | `auth_service.home_url_for()` | ลูกค้า → `/` · ไรเดอร์ → `/rider/` · ครัว → `/kitchen/` · เจ้าของ → `/console/` |
| กันเดารหัสผ่าน | `auth_service.authenticate_user()` | ผิด 5 ครั้ง/อีเมล (20 ครั้ง/IP) → ล็อก 15 นาที · ข้อความ error ไม่บอกว่าอีเมลมีจริงไหม |
| กัน open redirect | `redirect_url_after_login()` | `?next=` รับเฉพาะ path ในโดเมนเรา |
| Google Sign-In | `verify_google_credential()`, `login_or_register_with_google()` | ตรวจ ID token ฝั่งเซิร์ฟเวอร์ · ผูกกับบัญชีลูกค้าอีเมลเดียวกันได้ · **ไม่ผูกกับบัญชีพนักงาน** (พนักงานต้องใช้รหัสผ่าน) · ปุ่มซ่อนจนกว่าจะตั้ง `GOOGLE_CLIENT_ID` |
| แก้โปรไฟล์ | `services/user_service.update_profile()` | ชื่อ + เบอร์ (ตรวจ 10 หลักขึ้นต้น 0) |
| คำสั่งสร้างเจ้าของร้าน | `management/commands/create_owner.py` | ถามรหัสผ่านผ่าน prompt ไม่ค้างใน shell history |
| บัญชีทดสอบ | `management/commands/seed_dev_users.py` | 4 บทบาท `*@tmpp.test` · รหัสผ่านจาก `DEV_SEED_PASSWORD` ใน `.env` · ใช้ได้เฉพาะ DEBUG |

### หน้าลูกค้า
- **หน้าแรก `/`**: ถ้าล็อกอินเป็นลูกค้า แสดงแถบทักทาย + ปุ่ม "เพิ่มเบอร์โทรก่อนสั่ง" ถ้ายังไม่มีเบอร์ (สมัครด้วย Google จะยังไม่มี)
- **บัญชี `/account/`**: แก้ชื่อ/เบอร์, ที่อยู่ (ว่าง — มาใน M3), ออเดอร์ล่าสุด (ว่าง), สถานะเชื่อม Google, ออกจากระบบ
- header: เมนูผู้ใช้ (dropdown) · แถบล่าง: ปุ่ม "บัญชี" เปลี่ยนเป็น "เข้าสู่ระบบ" เมื่อยังไม่ล็อกอิน

### หน้าไรเดอร์ (`apps/delivery`)
- `RiderProfile`: ทะเบียนรถ, เปิด/ปิดรับงาน, เวลาเริ่ม, `current_location` (PostGIS, ใช้ใน M6)
- **`/rider/`**: ทักทาย, การ์ดสถานะ + ปุ่มใหญ่ "เริ่มรับงาน / หยุดรับงาน" (HTMX เปลี่ยนเฉพาะการ์ด ไม่โหลดหน้าใหม่), การ์ด "งานตอนนี้" (ว่าง — มาใน M6), ข้อมูลไรเดอร์
- ล็อกแถวตอนเปลี่ยนสถานะ (`select_for_update`) กันกดซ้ำจากสองแท็บ

### Console เจ้าของร้าน (`apps/console`)
- **`/console/`** ภาพรวม: จำนวนลูกค้า/ไรเดอร์/ครัว (ข้อมูลจริง) + การแก้ไขล่าสุด
- **`/console/staff/`** ไรเดอร์และพนักงาน: สร้างบัญชี (ไรเดอร์มีช่องทะเบียนรถ), ปิด/เปิดบัญชี (HTMX), ตั้งรหัสผ่านใหม่
  - ปิดบัญชี → เครื่องที่ล็อกอินอยู่หลุดทันที + ไรเดอร์ถูกตั้งเป็นปิดรับงาน
  - ตั้งรหัสผ่านใหม่ → session เก่าหลุดทั้งหมด
- **`AuditLog`**: ทุกการสร้าง/ปิด/เปิด/ตั้งรหัสผ่าน บันทึกผู้ทำ, IP, ก่อน/หลัง (ไม่เก็บรหัสผ่าน)
- console เรียก `accounts.services` / `accounts.selectors` เท่านั้น ไม่แตะ model User ตรงๆ

## 3. สิ่งที่ AI รันบนเครื่องพัฒนาให้ (user สั่ง "เปิด localhost ให้รัน")
- `pip install google-auth` · `makemigrations` · **`migrate`** (ฐานข้อมูล `tmpp` บนเครื่อง ยังไม่มีข้อมูลจริง)
- `seed_dev_users` สร้าง 4 บัญชีทดสอบ · เพิ่ม `DEV_SEED_PASSWORD` และ `GOOGLE_CLIENT_ID=` (ว่าง) ใน `.env`

## 4. ให้ user ทดสอบเอง
1. ดูรหัสผ่านบัญชีทดสอบใน `.env` (`DEV_SEED_PASSWORD`)
2. http://localhost:8000/auth/login/ → ลองล็อกอินทีละบัญชี: `customer@tmpp.test`, `rider@tmpp.test`, `kitchen@tmpp.test`, `owner@tmpp.test` ดูว่าไปถูกหน้า
3. ลองสมัครลูกค้าใหม่ที่ `/auth/register/`
4. ล็อกอินเจ้าของ → `/console/staff/` → สร้างบัญชีไรเดอร์ → ออก → ล็อกอินด้วยบัญชีใหม่
5. ลองใส่รหัสผิด 5 ครั้งติด ดูว่าถูกล็อก

**สร้างบัญชีเจ้าของจริง (ตอนขึ้น server):** `python manage.py create_owner --email <อีเมลเจ้าของ> --name "<ชื่อ>"`
**เปิด Google Sign-In:** สร้าง OAuth Client (Web) ใน Google Cloud Console → Authorized JavaScript origins ใส่ `http://localhost:8000` และ `https://tmth-th.com` → ใส่ Client ID ใน `GOOGLE_CLIENT_ID`
