# Module 03 — ชำระเงิน: QR พร้อมเพย์ + แนบสลิป + ตรวจด้วย EasySlip (M4 ในแผน)

> วันที่: 16/11/2569 · สถานะ: เสร็จ migrate บนเครื่องพัฒนาแล้ว · รอใส่ค่าจริง (พร้อมเพย์, บัญชี, EasySlip key) แล้วทดสอบโอนจริง

## 1. ขั้นตอน

```
ลูกค้าสั่ง -> [รอชำระเงิน] เห็น QR พร้อมเพย์ (ยอดอยู่ใน QR แล้ว) + เวลาที่ต้องจ่าย
          -> แนบสลิป -> [รอตรวจสลิป]
                Celery ส่งให้ EasySlip ตรวจ
                ├─ ผ่านครบทุกข้อ        -> [ชำระแล้ว รอครัวรับ]
                ├─ สลิปมีปัญหา          -> กลับ [รอชำระเงิน] + บอกเหตุผล ให้แนบใหม่ (ไม่เกิน 3 ครั้ง)
                └─ EasySlip ใช้ไม่ได้   -> คิว "ตรวจสลิป" ใน Console ให้เจ้าของกดอนุมัติ/ไม่ผ่าน
ไม่จ่ายภายใน 20 นาที -> [ยกเลิก] อัตโนมัติ (ออเดอร์ที่ส่งสลิปแล้วไม่ถูกยกเลิก)
```

## 2. ทำอะไรไปแล้ว (`apps/payments`)

| ส่วน | ไฟล์ | ทำไม |
|---|---|---|
| QR พร้อมเพย์ระบุยอด | `services/promptpay_service.py` | มาตรฐาน EMVCo · รองรับเบอร์ 10 หลัก / เลขบัตร 13 / e-Wallet 15 · CRC ตรวจเทียบกับ `binascii` แล้ว |
| เรียก EasySlip V2 | `services/easyslip_client.py` | แยก "สลิปมีปัญหา" (บอกลูกค้า) กับ "EasySlip ใช้ไม่ได้" (ส่งเจ้าของ) · timeout 20 วิ |
| ตรวจสลิปกับออเดอร์ | `services/slip_checks.py` | ต้องตรงครบ: รหัสธุรกรรมไม่เคยใช้ · **โอนเข้าบัญชีร้าน** (เทียบเลขที่ปิดบัง ต้องเห็น ≥ 4 หลัก) · **ชื่อผู้รับตรง** (ไม่สนคำนำหน้า, สระวรรณยุกต์ต้องตรง) · **ยอดตรงทุกสตางค์** · ร้านยังไม่ตั้งบัญชี = ห้ามอนุมัติอัตโนมัติ |
| ขั้นตอนหลัก | `services/slip_service.py` | แนบสลิป, ตรวจอัตโนมัติ, เจ้าของตรวจ, หมดเวลา |
| Celery | `tasks.py` | ตรวจสลิป (**ไม่เรียก API ภายนอกใน request** ตามกฎข้อ 3) + ยกเลิกออเดอร์ค้างทุกนาที (Celery beat) |
| ไฟล์สลิปส่วนตัว | `storage.py` | เก็บที่ `PRIVATE_MEDIA_ROOT` ไม่มี URL สาธารณะ · เปิดผ่าน `/payments/slips/<id>/image/` ที่ตรวจสิทธิ์ (เจ้าของร้าน หรือลูกค้าเจ้าของออเดอร์ · คนอื่น 404) · ห้าม cache |
| คำสั่งสำรอง | `manage.py expire_unpaid_orders` | ใช้ตอนไม่มี Celery beat |

### กันโกง / กันพลาด
- **สลิปเดียวจ่าย 2 ออเดอร์ไม่ได้** — รหัสธุรกรรม unique ในฐานข้อมูล (เฉพาะใบที่อนุมัติ) กันได้แม้ส่งพร้อมกัน
- **รูปเดิมเป๊ะส่งซ้ำ** — เช็ค hash ของไฟล์ ปฏิเสธทันทีไม่เสียโควต้า EasySlip
- **ไฟล์ปลอม** — ตรวจด้วย Pillow ว่าเป็นรูปจริง รับเฉพาะ JPG/PNG/WEBP ไม่เกิน 4 MB
- **แนบซ้ำพร้อมกัน 2 ครั้ง** — lock ออเดอร์ ครั้งที่สองถูก rollback
- **ออเดอร์ถูกยกเลิกระหว่างตรวจ แต่ลูกค้าโอนแล้ว** — สลิปไปคิวเจ้าของพร้อมข้อความ "ตรวจสอบและโอนคืน"
- **ราคาในสลิปต้องตรงกับ `Order.total`** ที่คิดฝั่งเซิร์ฟเวอร์

### หน้าลูกค้า (`/orders/<id>/`)
- รอชำระ: QR + ชื่อบัญชี + เลขพร้อมเพย์แบบปิดบัง + เวลาที่ต้องจ่าย + ปุ่มบันทึกรูป QR + ฟอร์มแนบสลิป + เหตุผลถ้าใบก่อนไม่ผ่าน + จำนวนครั้งที่เหลือ
- รอตรวจ: บอกว่าระบบตรวจ หรือร้านตรวจ (หน้าอัปเดตเองทุก 10 วิ)
- ชำระแล้ว: ยอดและเวลาที่จ่าย

### Console
- **`/console/slips/`** คิวสลิปรอตรวจ: รูปสลิป, ยอด, ลูกค้า, ใส่เลขอ้างอิง (กันซ้ำ), ปุ่ม "เงินเข้าแล้ว อนุมัติ" / "ไม่ผ่าน" (ต้องใส่เหตุผล ลูกค้าเห็น) + ประวัติตรวจล่าสุด · ตัวเลขแจ้งบนเมนู
- หน้ารายละเอียดออเดอร์: รายการสลิปทุกครั้ง + ดูรูป
- ทุกการอนุมัติ/ไม่ผ่านบันทึก AuditLog

### บั๊กที่เจอระหว่างทดสอบ และแก้แล้ว
- **test เขียนไฟล์สลิปลงโฟลเดอร์จริง** (39 ไฟล์) — storage จำ path ไว้ตั้งแต่ครั้งแรก ไม่อ่าน settings ใหม่ → เปลี่ยนให้อ่านทุกครั้ง + `conftest.py` ให้ทุก test ใช้โฟลเดอร์ชั่วคราว + test กันไว้ · ลบไฟล์ที่หลุดออกแล้ว (เก็บไว้เฉพาะสลิปทดสอบที่อยู่ในฐานข้อมูล 1 ไฟล์)

### ยังไม่ได้ทดสอบ (ต้องใช้ค่าจริง)
- **ไม่ได้ใส่เลขพร้อมเพย์ทดสอบ** ตั้งใจเว้นว่าง: ถ้าใส่เลขมั่วแล้วมีคนสแกนจ่ายจริง เงินจะเข้าคนอื่น · QR ทดสอบด้วย test แล้ว
- **ยังไม่ได้เรียก EasySlip จริง** (ไม่มีคีย์) · test ใช้ response จำลองตามเอกสาร V2
- Celery beat ยกเลิกออเดอร์อัตโนมัติ: บนเครื่องนี้ไม่มี Redis จึงไม่มี beat → ใช้ `python manage.py expire_unpaid_orders` แทนได้

## 4. ให้ user ทำ / ทดสอบ
ใส่ใน `.env` แล้วรีสตาร์ตเซิร์ฟเวอร์:
```
PROMPTPAY_ID=<พร้อมเพย์ร้าน>
SHOP_BANK_ACCOUNT=<เลขบัญชีที่ผูกพร้อมเพย์>
SHOP_BANK_CODE=<รหัสธนาคาร ตามเอกสาร EasySlip เช่น 004>
SHOP_ACCOUNT_NAMES=<ชื่อบัญชีไทย>,<ชื่อบัญชีอังกฤษ>
EASYSLIP_API_KEY=<คีย์>
```
1. สั่งอาหารราคาถูก (เช่นเมนูทดสอบ 1 บาท + ค่าส่ง) → สแกน QR ด้วยแอปธนาคารจริง ดูว่าชื่อบัญชี/ยอดถูก
2. แนบสลิปจริง → ควรเป็น "ชำระแล้ว" ภายในไม่กี่วินาที
3. ลองแนบสลิปเดิมกับอีกออเดอร์ → ต้องไม่ผ่าน "สลิปนี้ถูกใช้ไปแล้ว"
4. ลบ `EASYSLIP_API_KEY` ชั่วคราว → แนบสลิป → ไปอนุมัติที่ `/console/slips/`

## 5. ยังไม่ทำ (จดไว้)
- แจ้งเตือน FCM: สลิปรอตรวจ (เจ้าของ), ชำระแล้ว (ครัว/ลูกค้า), สลิปไม่ผ่าน (ลูกค้า) — M8
- คืนเงิน: ระบบไม่โอนเงินคืน เจ้าของโอนเองแล้วกดยกเลิกพร้อมเหตุผล

## 6. คำถามทบทวน (กฎข้อ 8)
1. ทำไมการเรียก EasySlip ต้องอยู่ใน Celery task ไม่ใช่ตอนลูกค้ากดส่งสลิปเลย
2. ถ้า EasySlip ล่มทั้งวัน ลูกค้าที่จ่ายแล้วจะค้างไหม ระบบทำอะไร
3. ถ้ามีคนเอาสลิปของคนอื่นที่โอนเข้าร้านเราด้วยยอดเท่ากันมาใช้ ระบบกันได้ด้วยอะไรบ้าง
