# Module 04 — จอครัว (KDS) (M5 ในแผน)

> วันที่: 16/11/2569 · สถานะ: เสร็จ · รอทดสอบเสียงบนแท็บเล็ต/มือถือจริงในครัว

## 1. ทำอะไรไปแล้ว

**หน้า `/kitchen/`** — ใช้ได้ทั้งบัญชีครัวและเจ้าของร้าน (ลูกค้า/ไรเดอร์ได้ 403) · ล็อกอินบัญชีครัวแล้วมาหน้านี้เอง

| ส่วน | ทำไม |
|---|---|
| 3 คอลัมน์: **ใหม่ (จ่ายแล้ว) → กำลังทำ → รอไรเดอร์รับ** | จอใหญ่เห็นพร้อมกัน · มือถือ/แท็บเล็ตแนวตั้งเป็นแท็บพร้อมตัวเลข (แท็บที่เลือกไม่เด้งกลับตอนบอร์ดรีเฟรช) |
| ใบออเดอร์ | เลข 4 ตัวท้ายตัวใหญ่, จำนวนในกล่องดำ, ตัวเลือก, **หมายเหตุต่อเมนูสีส้ม**, หมายเหตุออเดอร์กรอบเหลือง, นาทีที่รอตั้งแต่จ่าย · **เกิน 15 นาทีขึ้นกรอบแดง** |
| ปุ่มเดียวต่อขั้น | "รับออเดอร์" → "อาหารพร้อม" · ยกเลิก (ถามเหตุผล ลูกค้าเห็น + เตือนว่าต้องโอนคืน) |
| อัปเดตเอง | HTMX ถามบอร์ดทุก 5 วินาที **เฉพาะตอนแท็บเปิด** · กลับมาที่แท็บโหลดทันที · จำนวนออเดอร์ใหม่ขึ้นที่ชื่อแท็บ "(1) จอครัว" |
| **เสียงแจ้งเตือน** | ใช้เสียงกระดิ่งเดิมจากระบบเก่า (`static/sounds/bell-order.mp3`) · ดังเมื่อมีออเดอร์ใหม่ · **ดังซ้ำทุก 60 วิ ถ้ายังไม่มีใครกดรับ** · ต้องกด "เปิดเสียง" 1 ครั้งทุกครั้งที่เปิดจอ (กฎของเบราว์เซอร์) |
| กันจอดับ | กดเปิดเสียงแล้วขอ Wake Lock ให้แท็บเล็ตไม่ดับเอง (เครื่องไม่รองรับก็ไม่พัง) |
| ปิดรับออเดอร์ชั่วคราว | ครัวกดเองได้ตอนออเดอร์ล้น |
| เมนูหมด / มีขาย | กดจากจอครัวได้เลย หายจากหน้าร้านทันที |
| ออกจากร้านแล้ว | ออเดอร์ที่ไรเดอร์รับไปภายใน 30 นาที แสดงเลขสั้นๆ |

**โครงสร้าง:** `orders/selectors/kitchen_selector.py` (บอร์ด query คงที่), `orders/services/kitchen_service.py` (ปุ่ม → `transition_order()`), `orders/kitchen_views.py`, `templates/orders/kitchen/`, `static/js/kitchen.js`
- กดซ้ำ / มีคนเปลี่ยนสถานะไปก่อน → ขึ้นข้อความแจ้ง ไม่พัง ไม่บันทึกซ้ำ (lock แถวใน `transition_order`)
- ยกเลิก / ปิดร้าน / เมนูหมด จากจอครัว บันทึก AuditLog พร้อมชื่อคนกด
- ลบหน้าชั่วคราว `core/kitchen` แล้ว เปลี่ยนเป็น `orders:kitchen`

## 2. ผลตรวจ
- `pytest`: **145 passed** (เพิ่ม 11) — สิทธิ์ (ครัว/เจ้าของเข้าได้, ลูกค้า/ไรเดอร์ 403), ออเดอร์ที่ยังไม่จ่ายไม่ขึ้นจอครัว, รับ → พร้อม + ประวัติมีชื่อคนกด, **กดซ้ำได้ข้อความแจ้งและไม่บันทึกซ้ำ**, ข้ามขั้น/คำสั่งมั่วไม่ได้, ยกเลิกต้องมีเหตุผล + audit, ปิดร้าน/เมนูหมด, นาทีรอ + กรอบแดง, **จำนวน query บอร์ดคงที่**, ลูกค้าเห็น "ครัวกำลังทำ"
- **ทดสอบในเบราว์เซอร์**: แท็บเล็ต 768px (แท็บ) → กดรับออเดอร์ → แท็บกำลังทำ → กดอาหารพร้อม · จอ 1280px (3 คอลัมน์ ไม่ล้น) · **สร้างออเดอร์ใหม่จากหลังบ้าน แล้วขึ้นบนจอเองภายใน 6 วินาที** + ชื่อแท็บเปลี่ยน · ปุ่มเปิดเสียงทำงาน ไฟล์เสียงโหลดครบ

### ยังไม่ได้ทดสอบ
- **ได้ยินเสียงจริงไหม** — เบราว์เซอร์ในแอปตรวจได้แค่ว่าไฟล์โหลดและปุ่มเปิดเสียงทำงาน ต้องลองบนแท็บเล็ต/มือถือในครัว (เปิดเสียงเครื่อง, ไม่อยู่โหมดเงียบ)
- Wake Lock ต้องใช้ HTTPS (localhost ได้) — ทดสอบหลังขึ้น server

## 3. ข้อมูลทดสอบในฐานข้อมูลเครื่อง
ออเดอร์ `TM261116-HDUX` (สถานะ "อาหารพร้อม" รอไรเดอร์) และ `TM261116-9K76` (สร้างจาก shell เพื่อทดสอบ สถานะ "จ่ายแล้ว" อยู่คอลัมน์ใหม่) — ใช้ทดสอบหน้าไรเดอร์ใน M6 ต่อได้

## 4. ให้ user ทดสอบเอง
1. เปิด `/kitchen/` ด้วย `kitchen@tmpp.test` บนแท็บเล็ตหรือมือถือ → กด "เปิดเสียง"
2. อีกเครื่องล็อกอินลูกค้าสั่งอาหาร → ให้เจ้าของอนุมัติสลิปที่ `/console/slips/` → จอครัวต้องดังและขึ้นออเดอร์ภายใน 5 วิ
3. กดรับ → อาหารพร้อม → ดูที่ฝั่งลูกค้าว่าสถานะเปลี่ยนเอง
4. ลองกด "เมนูหมด / มีขาย" แล้วดูหน้าร้าน

## 5. ยังไม่ทำ (จดไว้)
- พิมพ์ใบออเดอร์ (เครื่องพิมพ์ใบเสร็จ) — ถ้าร้านมีเครื่องพิมพ์ บอกได้
- แจ้งเตือน FCM ถึงครัวเมื่อปิดจออยู่ — M8 (ตอนนี้ต้องเปิดจอครัวค้างไว้)

## 6. คำถามทบทวน (กฎข้อ 8)
1. ถ้าพนักงานครัวสองคนกด "รับออเดอร์" ใบเดียวกันพร้อมกัน ระบบเกิดอะไรขึ้น
2. ทำไมต้องกด "เปิดเสียง" ทุกครั้งที่เปิดจอครัว ทำให้ดังเองเลยไม่ได้หรือ
3. ทำไมจอครัวถามข้อมูลทุก 5 วินาที แต่ไม่ทำให้เซิร์ฟเวอร์หนักเมื่อออเดอร์เยอะขึ้น
