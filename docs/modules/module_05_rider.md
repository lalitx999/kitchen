# Module 05 — ไรเดอร์: รับงาน ส่งของ พิกัดสด + ลูกค้าติดตาม (M6 + ส่วนหนึ่งของ M7)

> วันที่: 16/11/2569 · สถานะ: เสร็จ · รอทดสอบ GPS บนมือถือจริง (ต้อง HTTPS หรือ localhost)

## 1. ขั้นตอนของไรเดอร์

```
เริ่มรับงาน -> งานใหม่ขึ้น (ดังเตือน) -> รับงาน
   ↓ (รับงานได้ตั้งแต่ลูกค้าจ่ายแล้ว ออกไปรอที่ร้านระหว่างครัวทำได้)
นำทางไปร้าน -> ครัวกด "อาหารพร้อม" -> "รับอาหารแล้ว ออกเดินทาง"  [กำลังไปส่ง]
   ↓
นำทางไปบ้านลูกค้า / โทรลูกค้า -> ถ่ายรูปตอนส่ง -> "ส่งสำเร็จ"  [ส่งสำเร็จ]
```
คืนงานได้ก่อนรับอาหาร · มีงานค้างอยู่จะกด "หยุดรับงาน" ไม่ได้

## 2. ทำอะไรไปแล้ว

### หน้าไรเดอร์ `/rider/` (ออกแบบสำหรับมือถือ ใช้มือเดียว)
| ส่วน | ทำไม |
|---|---|
| สถานะ + ยอดวันนี้ (กี่เที่ยว / ได้เท่าไร) | ไรเดอร์เห็นรายได้ตัวเอง (ตาม D3) |
| **งานของฉัน** | ปุ่มขั้นถัดไปปุ่มเดียว · นำทาง (เปิดแอป Google Maps ไปร้านหรือบ้านลูกค้าตามขั้น) · โทรลูกค้า · คืนงาน |
| **งานใหม่** | เฉพาะตอนเปิดรับงาน · ค่าส่งที่ไรเดอร์ได้ + ระยะ + รายการอาหาร · **เสียงเตือนงานใหม่** (`bell-rider.mp3`) |
| **ส่งสำเร็จต้องมีรูป** | เปิดกล้องหลังของมือถือ · บันทึกพิกัดตอนกดส่ง + ระยะจากหมุดลูกค้า (ถ้ามี GPS) ใช้ตรวจย้อนหลังเมื่อมีปัญหา |
| อัปเดตเองทุก 5 วิ | **หยุดอัปเดตระหว่างถ่ายรูป** ไม่อย่างนั้นรูปที่ถ่ายจะหาย (เจอตอนออกแบบ แก้ด้วย `data-busy`) |
| ส่งพิกัด GPS | ทุก ~5 วิ หรือเมื่อขยับ > 15 ม. ระหว่างเปิดรับงาน · กันจอดับ (Wake Lock) · กลับเข้าแอปส่งทันที · แถบบอก "ส่งตำแหน่งล่าสุด x วิที่แล้ว" เหลือง > 30 วิ แดง > 2 นาที พร้อมวิธีแก้ |

### พิกัดสด (`delivery/services/live_location_service.py`)
- เก็บ "ตำแหน่งล่าสุด" ใน cache 30 นาที · เขียนฐานข้อมูลไม่เกินนาทีละครั้ง · ส่งถี่กว่า 2 วิไม่บันทึก
- ไม่รับ 0,0 / นอกช่วง / GPS แม่นไม่พอ (> 1 กม.) · ปิดรับงานอยู่ไม่บันทึก
- **ส่งงานสุดท้ายเสร็จ = ลบตำแหน่งทิ้ง** (ลูกค้าไม่เห็นไรเดอร์หลังส่งเสร็จ)
- **Redis:** เครื่องพัฒนาใช้ cache ในหน่วยความจำได้เพราะ `runserver` เป็น process เดียว · server จริงหลาย worker ใช้ Redis ใน docker-compose (ไม่ต้องเลือกอะไรเพิ่ม)

### ลูกค้าติดตาม (หน้า `/orders/<id>/`)
- การ์ด "ไรเดอร์": ชื่อ ทะเบียน ปุ่มโทร · ระหว่างกำลังไปส่ง: **"ห่างจากบ้านประมาณ x กม."** / "ใกล้ถึงแล้ว" (< 500 ม.) · อัปเดตกี่วิที่แล้ว · ลิงก์ดูตำแหน่งบน Google Maps
- อัปเดตทุก 10 วิ เฉพาะตอนแท็บเปิด · **ตำแหน่งเก่า > 2 นาทีบอกตรงๆ ว่าสัญญาณอาจไม่ดี** ไม่เดาตำแหน่ง
- ส่งแล้ว: เวลาส่ง + ดูรูปตอนส่ง
- แผนที่ฝังในหน้า (หมุดไรเดอร์ขยับ) ทำเมื่อมี Google Maps API key — ตอนนี้ใช้ระยะทาง + ลิงก์แผนที่ ซึ่งใช้ได้โดยไม่มีค่าใช้จ่าย

### จุดอื่น
- จอครัว: แสดงชื่อไรเดอร์ที่รับงาน / "ยังไม่มีไรเดอร์รับงาน"
- Console รายละเอียดออเดอร์: ไรเดอร์, เวลารับงาน/รับอาหาร/ส่งถึง, รูปหลักฐาน, ระยะจากหมุดตอนกดส่ง
- รูปหลักฐานเก็บแบบส่วนตัว (ย้าย private storage ไป `core/storage.py` ใช้ร่วมกับสลิป) ดูได้เฉพาะเจ้าของร้าน/ลูกค้าเจ้าของออเดอร์/ไรเดอร์คนส่ง
- ตรวจรูปอัปโหลดย้ายไป `core/images.py` ใช้ร่วมกันทั้งสลิปและรูปส่งของ
- ไรเดอร์รับ/คืนงานผ่าน `order_service.assign_rider()/unassign_rider()` (lock แถว) · สถานะเปลี่ยนผ่าน `transition_order()` ที่เดียวเหมือนเดิม

## 3. ผลตรวจ
- `pytest`: **164 passed** (เพิ่ม 19) — งานขึ้นเฉพาะตอนออนไลน์, ครบเส้นทางรับ→รับอาหาร→ส่ง (รับอาหารก่อนครัวเสร็จไม่ได้), ส่งสำเร็จต้องมีรูปจริง, **ไรเดอร์ 2 คนรับงานเดียวกันไม่ได้ + คนอื่นทำขั้นต่อไปไม่ได้**, คืนงาน, มีงานค้างปิดรับงานไม่ได้, ลูกค้า/เจ้าของกดปุ่มไรเดอร์ไม่ได้, ยอดวันนี้, query คงที่, พิกัดบันทึก + เขียน DB ไม่เกินนาทีละครั้ง, พิกัดผิด 5 แบบ, ออฟไลน์ไม่บันทึก, **ลูกค้าเห็นตำแหน่งเฉพาะตอนกำลังส่ง + คนอื่นดูไม่ได้ + ส่งเสร็จลบตำแหน่ง**, ตำแหน่งเก่าบอกตรงๆ, สิทธิ์ดูรูปส่งของ
- ไม่มีไฟล์ test หลุดลงโฟลเดอร์จริง
- **ทดสอบในเบราว์เซอร์ (จอมือถือ 375px)**: เริ่มรับงาน → งานใหม่ขึ้นทันที → แถบ GPS บอกวิธีอนุญาตตำแหน่ง (เบราว์เซอร์ในแอปไม่มี GPS) → รับงาน → รับอาหาร → ปุ่มนำทาง/โทร/ถ่ายรูปขึ้น → **แนบรูปแล้วรอ 7 วิ รูปไม่หาย** → ส่งตำแหน่งจำลอง → ฝั่งลูกค้าเห็น "ห่างจากบ้านประมาณ 3.3 กม. อัปเดต 15 วินาทีที่แล้ว" → ส่งสำเร็จ "ได้ค่าส่ง ฿30" + ยอดวันนี้ 1 เที่ยว ฿30

### ยังไม่ได้ทดสอบ
- **GPS จริง, Wake Lock, กล้อง** — ต้องใช้มือถือจริง (GPS ใช้ได้เฉพาะ HTTPS หรือ localhost บนเครื่องเดียวกัน)
- เสียงงานใหม่ดังจริงไหม
- ตอนส่งสำเร็จในเบราว์เซอร์ไม่มี GPS → ระยะจากหมุดเป็นค่าว่าง (ถูกต้อง: ไม่แต่งพิกัด)

## 4. ข้อมูลทดสอบในฐานข้อมูลเครื่อง
`TM261116-HDUX` ส่งสำเร็จแล้ว (มีรูปหลักฐานทดสอบ) · `TM261116-9K76` ยังเป็นงานใหม่รอไรเดอร์

## 5. ให้ user ทดสอบเอง
1. มือถือน้องชาย: ล็อกอิน `rider@tmpp.test` (หรือบัญชีที่สร้างใน Console) → อนุญาตตำแหน่ง → "เปิดเสียง" → "เริ่มรับงาน"
2. อีกเครื่องสั่งอาหาร → อนุมัติสลิป → ไรเดอร์ต้องได้ยินเสียงงานใหม่ → รับงาน
3. ครัวกด "อาหารพร้อม" → ไรเดอร์ "รับอาหารแล้ว" → เดินออกไปสักพัก → ลูกค้าเห็นระยะลดลง
4. ถ่ายรูป → ส่งสำเร็จ → ดูรูปใน Console
**หมายเหตุ:** ทดสอบจริงบนมือถือผ่าน Wi-Fi เดียวกัน GPS จะไม่ทำงานเพราะไม่ใช่ HTTPS → ทดสอบเต็มรูปแบบหลังขึ้น server (M10)

## 7. คำถามทบทวน (กฎข้อ 8)
1. ทำไมหน้าไรเดอร์ต้องหยุดอัปเดตตัวเองระหว่างที่ไรเดอร์ถ่ายรูปส่งของ
2. ทำไมพิกัดไรเดอร์ไม่เขียนลงฐานข้อมูลทุก 5 วินาที แล้วลูกค้าเห็นตำแหน่งล่าสุดจากไหน
3. ถ้าไรเดอร์ปิดแอปกลางทาง ลูกค้าจะเห็นอะไร และทำไมไม่เดาตำแหน่งให้
