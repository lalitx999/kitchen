# Module 07 — แจ้งเตือน (FCM + ในเว็บ) (M8 ในแผน)

> วันที่: 17/11/2569 · สถานะ: เสร็จ · ตั้งค่า Firebase แล้ว (ใช้โปรเจกต์เดิม) · รอทดสอบ push เด้งจริงใน Chrome / มือถือ

## 1. ใครได้แจ้งเตือนเมื่อไร (`notifications/services/order_events.py` ที่เดียว)

| เหตุการณ์ | ผู้รับ |
|---|---|
| สลิปรอตรวจ (EasySlip ใช้ไม่ได้ / โหมด MANUAL) | เจ้าของร้าน |
| ชำระแล้ว | ลูกค้า · ครัว + เจ้าของ ("ออเดอร์ใหม่") · ไรเดอร์ที่เปิดรับงาน ("มีงานใหม่") |
| สลิปไม่ผ่าน | ลูกค้า (พร้อมเหตุผล) |
| ครัวกำลังทำ / ไรเดอร์กำลังไปส่ง / ส่งสำเร็จ | ลูกค้า |
| อาหารพร้อม | ไรเดอร์ที่รับงาน (ยังไม่มีคนรับ → ไรเดอร์ที่เปิดรับงานทุกคน) |
| **ไรเดอร์ใกล้ถึง (< 500 ม.)** | ลูกค้า (ครั้งเดียวต่อออเดอร์) |
| ยกเลิก | ลูกค้า (พร้อมเหตุผล) + ไรเดอร์ที่รับงาน |

## 2. ทำงานอย่างไร
1. **เก็บในระบบเสมอ** (`Notification`) → กระดิ่งบนหัวทุกหน้า (ลูกค้า/ไรเดอร์/ครัว/Console) มีตัวเลขที่ยังไม่อ่าน → หน้า `/notifications/` กดแล้วไปหน้าที่เกี่ยวข้องและนับเป็นอ่านแล้ว
2. **ส่ง push** ไปทุกเครื่องที่ผู้ใช้กด "เปิดการแจ้งเตือน" — ผ่าน **Celery** (เรียก FCM ใน request ไม่ได้ ตามกฎข้อ 3)
3. แจ้งเตือนสร้าง **หลัง commit เท่านั้น** — ถ้าการเปลี่ยนสถานะ rollback จะไม่มีแจ้งเตือนหลุด · ส่งแจ้งเตือนพังก็ไม่กระทบออเดอร์
4. token ที่ FCM บอกว่าใช้ไม่ได้ (ถอนการอนุญาต/ลบเว็บ) ปิดอัตโนมัติ · token เดียวกันเปลี่ยนบัญชีบนเครื่องเดียวกัน → push ไม่ไปผิดคน
5. ส่งซ้ำไม่ได้ (มี `sent_at`) · ยังไม่ตั้งค่า Firebase → ยังเห็นแจ้งเตือนในเว็บ แค่ไม่เด้ง

### หน้าเว็บ
- ปุ่ม **"เปิดการแจ้งเตือน"**: หน้าไรเดอร์, จอครัว, บัญชีลูกค้า, ภาพรวม Console, หน้าแจ้งเตือน (แสดงเฉพาะเมื่อตั้งค่า Firebase ครบ)
- เปิดเว็บอยู่ → แสดงเป็นข้อความด้านล่าง (toast) · ปิดแท็บ/ล็อกจอ → แจ้งเตือนของระบบ กดแล้วเปิดหน้านั้น
- service worker อยู่ที่ `/firebase-messaging-sw.js` (ต้องอยู่ root ของโดเมน) สร้างจาก template ใส่ค่าจาก `.env`
- เพิ่ม `manifest.webmanifest` → **iPhone ต้อง "เพิ่มไปยังหน้าจอโฮม" ก่อน (iOS 16.4+)** ถึงรับ push ได้ ปุ่มบอกวิธีให้เอง
- เวลาภาษาไทย "5 นาทีที่แล้ว" (ตัวกรอง `ago_th` — ของ Django แปลไทยไม่ครบ)

## 3. ผลตรวจ
- `pytest`: **198 passed** (เพิ่ม 18) — ชำระแล้วแจ้งลูกค้า/ครัว/เจ้าของ/ไรเดอร์ออนไลน์ (ไรเดอร์ออฟไลน์ไม่ได้), สลิปไม่ผ่านพร้อมเหตุผล, อาหารพร้อมไปถึงเฉพาะไรเดอร์ที่รับงาน, ยกเลิกแจ้งลูกค้า+ไรเดอร์, **rollback แล้วไม่มีแจ้งเตือน**, สลิปรอตรวจแจ้งเจ้าของ, **ใกล้ถึงแจ้งครั้งเดียว** แม้ส่งพิกัดหลายครั้ง, ข้ามบัญชีที่ปิด, แจ้งเตือนพังไม่กระทบขั้นตอน, ส่ง push (FCM จำลอง) + ไม่ส่งซ้ำ + ปิด token เสีย, ไม่มีค่า Firebase ยังเก็บแจ้งเตือน, ลงทะเบียนเครื่อง + ย้ายเจ้าของ token, เปิดแจ้งเตือน + กันลิงก์ออกนอกเว็บ, เปิดของคนอื่นไม่ได้, layout ตามบทบาท, ปุ่ม/สคริปต์แสดงเฉพาะเมื่อตั้งค่า, service worker ที่ root, เวลาไทย
- **ทดสอบในเบราว์เซอร์ (มือถือ 375px)**: ยกเลิกออเดอร์ทดสอบ → กระดิ่งลูกค้าขึ้น 1 → หน้าแจ้งเตือน → กดแล้วไปหน้าออเดอร์ + กระดิ่งหายเป็นอ่านแล้ว · service worker เปิดได้ที่ root
- เจอระหว่างทดสอบ: เวลาขึ้น "0 minutesที่แล้ว" (ภาษาปน) → ทำตัวกรองภาษาไทยเอง + test

### ยังไม่ได้ทดสอบ
- **push เด้งจริง** — ยังไม่มีค่า Firebase ในโปรเจกต์ใหม่ และ push บนมือถือต้องใช้ HTTPS (localhost บนคอมเครื่องเดียวกันได้)
- FCM ฝั่งเซิร์ฟเวอร์จริง (test ใช้ตัวจำลอง)

## 4. ตั้งค่า Firebase — ทำแล้ว 17/11/2569 (user อนุญาตให้คัดลอกจากโปรเจกต์เดิม)
- service account คัดลอกไปที่ `~/.config/tmpp/firebase-service-account.json` (**นอกโปรเจกต์**, สิทธิ์ 600 อ่านได้คนเดียว) → `FIREBASE_CREDENTIALS_PATH`
- ค่าฝั่งเว็บ 6 ค่า (API key, auth domain, project id, sender id, app id, VAPID) คัดลอกจาก `food/frontend/.env.local` ลง `.env` (ไม่ได้แสดงค่าในแชท)
- **ตรวจแล้ว:** ขอ access token จาก Google ได้ · FCM dry run ด้วย token ปลอมได้ `InvalidArgumentError` (ผ่านการยืนยันตัวตน ปฏิเสธแค่ token) · ในเบราว์เซอร์: Firebase SDK โหลดได้, รองรับ messaging, service worker ลงทะเบียนที่ `/` และทำงาน
- **ยังไม่ได้ทดสอบ:** ขอ token จริง + push เด้ง — เบราว์เซอร์ในแอปปิดสิทธิ์แจ้งเตือนไว้ (ปุ่มแสดง "ถูกปิดแจ้งเตือนไว้" ถูกต้อง)
- ตอนขึ้น server (M10): คัดลอกไฟล์ service account ไปเก็บบน server นอกโฟลเดอร์โค้ด แล้วตั้ง path ใน `.env` ของ server

### ทดสอบ push จริงด้วยตัวเอง
1. เปิด `http://localhost:8000/rider/` ใน **Chrome** ของเครื่องนี้ (localhost ใช้ push ได้โดยไม่ต้อง HTTPS) → ล็อกอิน `rider@tmpp.test` → "เริ่มรับงาน" → "เปิดการแจ้งเตือน" → อนุญาต
2. ย่อหน้าต่าง Chrome → อีกเบราว์เซอร์/แท็บไม่ระบุตัวตน ล็อกอินลูกค้าสั่งอาหาร → เจ้าของอนุมัติสลิป
3. ต้องมีแจ้งเตือนของ macOS "มีงานใหม่" กดแล้วเปิดหน้าไรเดอร์
**หมายเหตุ:** เครื่องนี้ไม่มี Redis/Celery worker → push ส่งทันทีในกระบวนการเดียวกัน (eager) ใช้ทดสอบได้

## 4.1 วิธีตั้งค่าเอง (เผื่อเปลี่ยนโปรเจกต์ Firebase)
โปรเจกต์เดิมมีค่าครบแล้ว (service account + ค่าฝั่งเว็บใน `food/frontend/.env.local`) ใช้โปรเจกต์ Firebase เดิมได้:
1. เก็บไฟล์ service account ไว้ **นอกโฟลเดอร์โปรเจกต์** (เช่น `~/secrets/tmpp-firebase.json`) แล้วใส่ path ใน `FIREBASE_CREDENTIALS_PATH`
2. ใส่ `FIREBASE_API_KEY`, `FIREBASE_AUTH_DOMAIN`, `FIREBASE_PROJECT_ID`, `FIREBASE_MESSAGING_SENDER_ID`, `FIREBASE_APP_ID`, `FIREBASE_VAPID_KEY`
3. Firebase Console > Authentication > Settings > Authorized domains: เพิ่ม `tmth-th.com`
4. ทดสอบ: เปิด `http://localhost:8000` บนคอม → ล็อกอินไรเดอร์ → "เปิดการแจ้งเตือน" → อีกแท็บให้ลูกค้าสั่ง+อนุมัติสลิป → ต้องเด้ง "มีงานใหม่"

## 5. คำถามทบทวน (กฎข้อ 8)
1. ทำไมแจ้งเตือนถูกสร้าง "หลัง commit" ไม่ใช่ทันทีที่เปลี่ยนสถานะ
2. ถ้า Firebase ล่มทั้งวัน ลูกค้า/ครัวยังรู้สถานะออเดอร์ได้จากไหน
3. ทำไม iPhone ต้องเพิ่มเว็บไปที่หน้าจอโฮมก่อนถึงจะได้รับแจ้งเตือน
