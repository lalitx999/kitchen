ฐานของงานออกแบบใหม่ (PLAN.md §11) · ไม่มี migration · ไม่มีคีย์ใหม่

## 1. แอปแยกตามบทบาท (manifest 3 ตัว)
| ไฟล์ | ชื่อบนหน้าจอโฮม | `id` / `start_url` | ใช้ใน layout |
|---|---|---|---|
| `static/manifest.webmanifest` | TMPP | `/start/` (**ห้ามเปลี่ยน**) | ลูกค้า, console, หน้าอื่น |
| `static/manifest-kitchen.webmanifest` | TMPP ครัว | `/kitchen/` | `layouts/kitchen.html` |
| `static/manifest-rider.webmanifest` | TMPP ไรเดอร์ | `/rider/` | `layouts/rider.html` |

- `base.html` มี block `manifest` และ `app_name` ให้ layout เปลี่ยนได้
- ทำไม id ของลูกค้าห้ามเปลี่ยน: เบราว์เซอร์ใช้ `id` แยกว่าเป็นแอปไหน ถ้าเปลี่ยน แอปที่ลูกค้าติดตั้งไว้แล้วจะกลายเป็นแอปเก่าที่ไม่มีใครดูแล
- ครัว/ไรเดอร์ที่ติดตั้งแอปลูกค้าไว้ก่อนหน้านี้ยังใช้ได้ (`/start/` ส่งไปหน้าตามบทบาทอยู่แล้ว) แต่แนะนำให้ลบไอคอนเดิม แล้วติดตั้งใหม่จากหน้าครัว/หน้าไรเดอร์ จะได้ไอคอนชื่อถูก
- ไอคอนยังเป็นรูปเดียวกันทั้ง 3 แอป ต่างกันที่ชื่อ (ถ้าต้องการไอคอนคนละสี ทำไฟล์ PNG เพิ่มทีหลังได้)

## 2. Service worker (`templates/notifications/firebase-messaging-sw.js`)
- **หน้า HTML ไม่ถูกเก็บ:** ราคาและสถานะออเดอร์โหลดจากเซิร์ฟเวอร์เสมอ เก็บไว้แค่หน้า offline (เหมือนเดิม)
- **เก็บไฟล์ static ที่มี hash ในชื่อ** (`app.3f2a9c1b7d4e.js`): ชื่อไฟล์เปลี่ยนทุกครั้งที่เนื้อหาเปลี่ยน จึงเก็บได้ตลอดโดยไม่ได้ของเก่า · ไม่เกิน 150 ไฟล์ เก่าสุดลบก่อน · ตอนพัฒนาบนเครื่อง (ไม่มี hash) ไม่เก็บ
- **รุ่นของไฟล์:** `apps/core/selectors/asset_selector.py` เอา `manifest_hash` ของ `collectstatic` มาใส่ในบรรทัด `// assets: ...` → deploy ที่ไฟล์ static เปลี่ยน = ไฟล์ service worker เปลี่ยน = มือถือติดตั้งตัวใหม่
- **แถบ "มีเวอร์ชันใหม่ แตะเพื่อโหลด"** (`#tm-update`): ขึ้นเมื่อ service worker ตัวใหม่เข้ามาคุมหน้าที่เปิดค้างอยู่ · จอครัว/ไรเดอร์ที่เปิดค้างทั้งวันจะเช็คเวอร์ชันทุก 30 นาที · ถ้าไรเดอร์กำลังถ่ายรูปส่งของ จะถามก่อนโหลด (รูปจะหาย)

## 3. หน้าตาแบบแอป (`static/js/app.js`, `static/css/tmpp.css` ส่วน "M12 แบบแอป")
| เรื่อง | ทำอะไร | หมายเหตุ |
|---|---|---|
| ปุ่มย้อนกลับ | หัวแอปมีปุ่ม `<` เฉพาะแอปที่ติดตั้งแล้ว และหน้าที่ไม่ใช่หน้าหลัก (`data-roots`) · มาจากหน้าอื่นในเว็บ = ย้อนกลับ, เปิดจากแจ้งเตือน = ไปหน้าหลัก | จอ < 400px ซ่อนชื่อร้านข้างโลโก้ กันปุ่มล้น |
| เปลี่ยนหน้า | หัวแอปกับแถบล่างอยู่นิ่ง เฟดเฉพาะเนื้อหา (View Transitions) · ปิดเองเมื่อมือถือตั้ง "ลดการเคลื่อนไหว" | ใช้ CSS ล้วน ไม่ใช้ `hx-boost` (ดูข้อ 5) |
| โครงร่างระหว่างโหลด | แตะเมนู → หน้าเลือกอาหารเปิดทันทีพร้อมโครงร่าง แล้วค่อยแทนด้วยของจริง · โหลดไม่สำเร็จ = ปิดหน้าต่าง + แจ้ง | กระพริบด้วยสีพื้นเรียบ (ห้าม gradient) |
| ดึงลงเพื่อโหลดใหม่ | เฉพาะแอปที่ติดตั้งแล้วบนจอสัมผัส · หน้าที่มีส่วนโหลดเอง (บอร์ดครัว, งานไรเดอร์) โหลดแค่ส่วนนั้น · ไม่โหลดทั้งหน้าเมื่อพิมพ์ฟอร์มค้างไว้/กำลังถ่ายรูป · ไม่ทำงานบนแผนที่และในหน้าต่าง | ใส่ `data-no-ptr` ที่ element ที่ไม่ต้องการ |
| ตัวเลขบนไอคอน | ครัว = ออเดอร์ที่ยังไม่รับ, ไรเดอร์ = งานใหม่ (ตอนเปิดรับงาน), หน้าอื่น = แจ้งเตือนที่ยังไม่อ่าน · อัปเดตทุกครั้งที่บอร์ด/รายการงานโหลดใหม่ | Android/คอมเท่านั้น iPhone ไม่รองรับ |
| สีแดง | เพิ่มตัวแปร `--tm-danger` แทน `#dc2626` ที่เขียนตรงๆ 2 จุด | กฎ "สีจากตัวแปรเท่านั้น" |

## 5. ทางเลือกที่ไม่ได้ใช้
- **`hx-boost` ทั้งเว็บ** (เปลี่ยนหน้าด้วย HTMX ไม่โหลดใหม่): ลื่นกว่าเล็กน้อย แต่หน้าที่มี script ของตัวเอง (Google Maps, kitchen.js, rider.js, push.js) จะไม่ถูกเรียกใหม่หลังเปลี่ยนหน้า เสี่ยงพังหลายจุด → ใช้ View Transitions ของ CSS แทน ได้ความรู้สึกคล้ายกันโดยไม่ต้องแตะ script เดิม
- **เก็บหน้า HTML ไว้เปิดตอนออฟไลน์:** ลูกค้าอาจเห็นราคา/สถานะเก่า ขัดกับกฎ "ราคาคิดฝั่งเซิร์ฟเวอร์" → ไม่ทำ

## 6. ตรวจสอบ
- AI (เครื่อง Linux, รันใน Docker image ของโปรเจกต์ + PostGIS ของ `docker-compose.yml`): `check` ผ่าน, `makemigrations --check` ไม่มีอะไรค้าง, **pytest 260 passed** (ใหม่ 5 ข้อใน `test_pwa.py`)
- AI ทดสอบในเบราว์เซอร์ localhost (375px และ 768px): service worker ทำงาน, หน้าลูกค้า/ครัว/ไรเดอร์ใช้ manifest ของตัวเอง, ปุ่มย้อนกลับขึ้นเฉพาะหน้าที่ไม่ใช่หน้าหลัก + ซ่อนชื่อร้านที่ 375px ไม่ล้น, แตะเมนูแล้วเห็นโครงร่าง 5 ชิ้นก่อนข้อมูลจริง, แถบ "มีเวอร์ชันใหม่" และวงกลมโหลดแสดงถูกตำแหน่ง, ไม่มี error ใน console
- ยังทดสอบไม่ได้บนคอม (ต้องเป็นแอปที่ติดตั้งบนมือถือจริง): ท่าดึงลงด้วยนิ้ว, ตัวเลขบนไอคอน, แถบเวอร์ชันใหม่หลัง deploy จริง
- รันเทสต์บนเครื่องนี้ (ไม่ต้องลง GDAL ในเครื่อง):
  ```
  docker compose --env-file .env up -d db
  docker run --rm --network host -v "$PWD":/app -e DJANGO_SETTINGS_MODULE=config.settings.local tmpp-dev-test python -m pytest -p no:cacheprovider
  ```
  (`tmpp-dev-test` = image จาก `Dockerfile` + `requirements/local.txt` · dev server: `.claude/launch.json` ชื่อ `tmpp-django-docker`)
- ทดสอบบนมือถือจริงหลัง deploy (ไม่มี migration):
  1. หน้าครัว → ติดตั้ง → ไอคอนชื่อ "TMPP ครัว" เปิดแล้วเข้าจอครัว · ทำเหมือนกันกับไรเดอร์
  2. แอปลูกค้า: เปิดหน้าออเดอร์ → มีปุ่ม `<` · หน้าเมนูไม่มี
  3. ดึงลงที่จอครัว → บอร์ดโหลดใหม่ (ไม่กระพริบทั้งหน้า)
  4. deploy รอบถัดไปที่แก้ CSS/JS → จอครัวที่เปิดค้างขึ้นแถบ "มีเวอร์ชันใหม่" ภายใน 30 นาที
  5. Android: มีออเดอร์ใหม่ → ไอคอน "TMPP ครัว" มีตัวเลข
