## 2. หน้างาน: ขั้นตอนในแผ่นล่าง
ไปร้าน → **ถึงร้านแล้ว** → (ครัวกด "อาหารพร้อม" ปุ่มขึ้นเองใน 5 วิ) → **รับอาหารแล้ว ออกเดินทาง** → **ถึงแล้ว ถ่ายรูป** (1–4 รูป) → **ส่งสำเร็จ** → หน้าสรุป
- ระยะ/เวลา: คิดในมือถือจาก GPS (`rider.js` ส่ง event `tmpp:rider-position` → `rider_job.js`) เป็นระยะเส้นตรง เวลาประมาณที่ 25 กม./ชม. บอกบนจอว่าเป็นค่าประมาณ · ไม่มี GPS / GPS เงียบเกิน 1 นาที = บอกตรงๆ
- แผนที่ (U3): หมุดร้าน (ดำ) บ้านลูกค้า (ชมพู) ไรเดอร์ (เขียว) + **เส้นตรง** สีชมพูจากตัวแปร `--tm-brand` · ไม่ใช้ Directions API · ปุ่ม "นำทาง" เปิดแอป Google Maps · ไม่มี `GOOGLE_MAPS_API_KEY` = กล่องบอกวิธีตั้ง ไม่โหลดสคริปต์แผนที่
- ปุ่มโทร: ก่อนรับอาหาร = โทรร้าน, กำลังไปส่ง = โทรลูกค้า · คืนงานได้เฉพาะก่อนรับอาหาร (คืนแล้วกลับหน้าแรก)
- ฟอร์มรูปหลักฐานย้ายจากการ์ดในหน้าแรกมาไว้ที่นี่ (`delivery/_proof_form.html`) ยังกันรูปหายตอนกลับจากกล้องเหมือนเดิม (`data-busy`)

## 3. "ถึงร้านแล้ว" (มี migration)
- `Order.rider_arrived_at` (`orders/0005_order_rider_arrived_at`) · ไม่ใช่สถานะออเดอร์ จึงไม่ผ่าน `transition_order` แต่บันทึก `OrderStatusLog` ให้ดูย้อนหลังได้
- `order_service.mark_rider_arrived()` lock แถว, ต้องเป็นงานของตัวเอง, ก่อนรับอาหารเท่านั้น, กดซ้ำไม่บันทึกซ้ำ · `unassign_rider()` ล้างค่าเมื่อคืนงาน
- จอครัว: ใบออเดอร์ขึ้น "ไรเดอร์ … ถึงร้านแล้ว HH:MM" (สีเขียว `--tm-action`) และ "… รออยู่ที่ร้าน"
